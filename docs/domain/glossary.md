# Глосарій ViloreHome

1. **Домен** — предметна область системи; для ViloreHome це каталог товарів для дому та прототип процесів замовлення, оплати й складу.
2. **Піддомен** — частина предметної області з окремою відповідальністю, наприклад каталог або замовлення.
3. **Bounded context (обмежений контекст)** — межа, у якій діє окрема доменна модель; у прототипі це модулі `Users`, `Catalog`, `Orders`, `Payments` та `Inventory`.
4. **Сутність (Entity)** — доменний об'єкт з ідентичністю, наприклад `Order` із GUID `Id`.
5. **Агрегат (Aggregate)** — група доменних об'єктів із коренем, через який мають координуватися зміни. `Order` містить позиції `OrderItem` та керує додаванням позицій і переходами статусу; у поточному прототипі кількість позиції можна змінити напряму через `OrderItem.ChangeQuantity`, минаючи перевірку статусу замовлення.
6. **Інваріант** — правило, яке доменна операція має зберігати: наприклад, резерв складу не може перевищувати доступний залишок.
7. **Життєвий цикл замовлення** — дозволені зміни `OrderStatus`: `Pending`, `Confirmed`, `Paid`, `Shipped`, `Completed` або `Cancelled`; переходи контролюються методами `Order`.
8. **Ціна-знімок** — ціна одиниці `OrderItem.UnitPrice`, що передається під час додавання позиції та не залежить від подальшої зміни `Product.Price`.
9. **Резерв товару** — частина фізичного залишку, тимчасово відведена під замовлення; у моделі обліковується через `ReservedQuantity`.
10. **Контекстна мапа (Context map)** — схема bounded contexts та їхніх логічних взаємозв'язків; діаграма цього прототипу не означає, що модулі вже інтегровані між собою.
