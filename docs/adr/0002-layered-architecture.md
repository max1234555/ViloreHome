# ADR 0002: Шарова архітектура бекенду

- **Статус:** прийнято
- **Дата:** 2026-11-15

## Контекст і рішення

Використовуємо логічні шари `api/`, `service/` та `domain/`, не перейменовуючи наявні каталоги проєкту. Нижче вказано їх фактичне розташування для поточного CRUD.

| Логічний шар | Поточні файли | Відповідальність |
|---|---|---|
| `api/` | `Web-prog_server/Controllers/ItemsController.cs`, `HealthController.cs` | HTTP-маршрути, прийом запитів, статуси та HTTP-відповіді |
| `service/` | `Web-prog_server/Services/Items/IItemService.cs`, `ItemService.cs`, `ItemDtos.cs` | CRUD-сценарії, бізнес-валідація, DTO та результати операцій |
| `domain/` | `Web-prog_server/Models/Item.cs` | Модель товару з `Id`, `Name`, `Category`, `Price` |
| Доступ до даних | `Web-prog_server/Data/AppDbContext.cs` | EF Core та набір товарів у SQLite |

Інші класи в `Web-prog_server/Domain/` є прототипами доменних моделей і поки не використовуються контролером Items.

## Напрямок залежностей

```text
HTTP-клієнт
    -> Controllers (api)
    -> IItemService / ItemService (service)
    -> AppDbContext (доступ до даних)
    -> SQLite

ItemService -> Item (модель домену)
```

Контролер отримує `IItemService` через DI і не звертається до `AppDbContext` напряму. Сервіс виконує операцію, використовує контекст даних і повертає DTO/результат, який контролер перетворює на HTTP-відповідь.

## Правила та заборонені зв'язки

1. Контролери не виконують запити до БД і не містять бізнес-логіки; вони делегують роботу сервісам.
2. Сервіси не залежать від HTTP-типів на кшталт `ControllerBase` чи `IActionResult`.
3. Модель `Item` не залежить від контролерів або API DTO.
4. Не створювати циклічних залежностей між шарами.
5. Для поточного проєкту сервіс напряму використовує `AppDbContext`; окремий repository шар не заявляється як наявний.

## Наслідки

Контролери залишаються тонкими, а логіку CRUD можна тестувати окремо від HTTP. Водночас `ItemService` наразі залежить від EF Core через `AppDbContext`; за зростання складності спосіб доступу до даних можна переглянути окремим рішенням.
