# Бізнес-документ проєкту ViloreHome

## 1. Назва системи й короткий опис
**ViloreHome** — це сучасна вебплатформа, призначена для каталогізації, управління та перегляду товарів для дому, інтер'єру та декору. Система об'єднує в собі потужний та безпечний бекенд-сервіс на базі ASP.NET Core та зручний інтерфейс користувача на React. 

Платформа дозволяє користувачам швидко переглядати актуальний асортимент товарів, фільтрувати їх за категоріями та ціною, а також взаємодіяти з інвентарем у реальному часі завдяки інтегрованій базі даних SQLite. Проєкт створений з акцентом на масштабованість, швидкість роботи та легкість у розширенні функціонала.

## 2. Хто користувачі (ролі)
* **Гість / Покупець:** Користувач, який заходить на сайт, переглядає каталог товарів, шукає необхідні речі для дому та переглядає їх вартість.
* **Адміністратор / Менеджер:** Користувач з розширеними правами, який керує каталогом (додає нові товари, редагує їх ціни, категорії та описи) та слідкує за станом бази даних.

## 3. Основні сценарії використання (Use Cases)
1. **Перегляд каталогу товарів:** Користувач відкриває головну сторінку, натискає кнопку завантаження та отримує актуальний список товарів із сервера.
2. **Фільтрація та сортування:** Користувач переглядає назви товарів, категорії (наприклад, декор) та ціни у гривнях.
3. **Додавання нового товару (Адмін):** Адміністратор через панель управління або API додає новий товар до бази даних.
4. **Обробка помилок підключення:** Якщо бекенд-сервер недоступний, система коректно повідомляє користувача про помилку з'єднання.

## 4. Функціональні вимоги
* Система повинна надавати REST API (`/api/Items`) для отримання списку товарів.
* Інтерфейс (React) повинен асинхронно завантажувати дані без перезавантаження сторінки.
* Підтримка стабільних станів завантаження (loading) та обробки помилок (error handling).
* Зберігання даних у реляційній базі даних SQLite за допомогою Entity Framework Core.

## 5. Нефункціональні вимоги
* **Швидкодія:** Час відповіді сервера на стандартний запит каталогу має становити менше 200 мс.
* **Зручність (UX/UI):** Інтуїтивно зрозумілий мінімалістичний інтерфейс, адаптований під різні роздільні здатності екранів.
* **Безпека:** Захищений обмін даними та валідація вхідних запитів на рівні API.

## 6. Обмеження (Що система точно не буде робити)
* Система **не містить** вбудованої платіжної системи для онлайн-окупівлі (на цьому етапі немає інтеграції з банками).
* Система **не підтримує** складну багатофакторну аутентифікацію на перших етапах розробки.
* Проєкт наразі розгорнутий локально і не призначений для продакшн-навантажень тисяч користувачів одночасно.
